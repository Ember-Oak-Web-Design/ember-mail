# Ember Mail — CLAUDE.md

A native macOS mail client (SwiftUI) for Ember & Oak. It hosts a custom-domain business inbox over
IMAP/SMTP and a Google account (Gmail API), with read receipts on outgoing mail and Google Calendar
integration. End-user setup lives in `docs/SETUP.md`.

## Goals (in priority order)
1. **Easy to use, modern, slick.** Native macOS look (NavigationSplitView, SF Symbols, materials),
   ember-orange accent (`Theme.accent`), avatars, relative dates, swipe actions, keyboard shortcuts.
   Never block the UI: show cached data instantly and refresh in the background.
2. **Read receipts on every sent email** (on by default, toggle per message in Compose).
3. **Google Calendar** visible everywhere: full Calendar view (day/week/month) and a "Today"
   inspector next to the inbox.
4. Two account types side by side, plus a unified "All Inboxes".

## Build / run / test (important: toolchain quirks)
Only **Command Line Tools** are installed (no Xcode). Two things are broken in this install:
- `swift build` / SwiftPM crashes (dyld symbol mismatch in `swift-package`). **Don't use SwiftPM.**
- The default SDK (MacOSX27) is newer than the compiler (Swift 6.3), so **pin `MacOSX26.5.sdk`**.

So everything compiles with `swiftc` directly via scripts:
- `./scripts/build-app.sh` → `build/Ember Mail.app` (release, ad-hoc signed).
  Flags: `--debug` (fast compile), `--run` (launch), `--install` (copy to `~/Applications`).
  Compiler output goes to `build/build.log`; errors are printed.
- Signing: `./scripts/setup-signing.sh` (run once by the user in Terminal; needs their password) creates a
  trusted self-signed "Ember Mail Local Signing" identity. `build-app.sh` uses it when it's valid, otherwise it
  signs ad-hoc. (Keychain prompts no longer depend on this, see the secrets note below, but a stable identity is
  still nicer for notifications and the login item.)
- `./scripts/release.sh X.Y.Z ["notes"]` (from a clean, pushed `main`) builds with that version, zips, writes a `.sha256`, and creates a GitHub
  Release `vX.Y.Z`. `build-app.sh --version X.Y.Z` stamps the version; `EMBER_SIGN_ID` / `EMBER_NOTARY_PROFILE` enable Developer ID signing and notarization.
- `./scripts/test.sh` compiles `Models/` + `Services/` with `Tests/main.swift` (a plain assertion runner;
  there's no XCTest) and runs it. Keep it passing; add cases for any parser change.
- Quick typecheck: `swiftc -parse-as-library -target arm64-apple-macos14.0 -sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk -typecheck $(find Sources/EmberMail -name '*.swift')`
- `Package.swift` is kept only for a future working toolchain.
- Deployment target macOS 14 (the user is on macOS 26). Guard newer APIs with `#available`.
  Watch for macOS 15+-only APIs (e.g. `Color.mix`): they compile against the 26 SDK but break the
  14 target.
- Macros: Observation (`@Observable`) works. SwiftData `@Model` and `#Preview` do **not**, so don't use them.
- The app must run from the `.app` bundle (notifications, keychain, mailto handler need the bundle id
  `com.emberoak.EmberMail`).
- No third-party Swift dependencies. Keep it that way unless there's a very strong reason.
- Screen capture isn't permitted from the agent shell; verify UI changes by asking the user.

## Architecture
- `AppState` (`@MainActor @Observable`) owns accounts, one `MailProvider` per account, the sidebar
  selection, the message list, loaded bodies, and optimistic actions (each reverts and shows a banner on
  failure). Views read it via `@Environment(AppState.self)`. Calendar and read receipts live in
  `app.calendar` / `app.tracking`.
- `MailProvider` unifies IMAP and Gmail: `mailboxes`, `messages`, `search`, `body`, `unreadCount`,
  `setRead`, `setFlagged`, `archive`, `trash`, `send`. Providers are actors.
- **IMAP concurrency:** `IMAPClient` is an actor, but actor methods interleave across `await`s. Every
  operation goes through `withRetry`, which holds a FIFO lock (`lock()`/`unlock()`) for its whole duration so
  commands never interleave on the single connection. Never call one `withRetry` method from inside another
  (it would deadlock); use `select`/`ensureSelected`/`execute` inside. A fake-server test proved that removing
  the lock hangs the client.
- IMAP: list fetch = `HEADER.FIELDS` + `BODY.PEEK[TEXT]<0.2048>` for snippets; the full body comes from
  `BODY.PEEK[]` plus an explicit `\Seen` store. Sent copies are APPENDed to Sent after SMTP. Archive
  creates an "Archive" folder if none exists.
- Gmail: REST. `format=metadata` for lists, `format=raw` for bodies, parsed by our MIME parser so
  both account types share one rendering path. Gmail saves sent mail itself; Bcc is passed in the raw
  message (Gmail strips it).
- Compose windows: `WindowGroup(for: ComposeDraft.self)`; `ComposeDraft` must stay Codable + Hashable.
  The body is written as plain text and converted to HTML (`MIMEBuilder.html`), then sent as
  multipart/alternative with QP encoding.
- Secrets live **only in the Keychain**, in ONE generic-password item (`vault-v3`, base64 JSON dictionary)
  read once per launch and cached (`Keychain` in Storage.swift): IMAP passwords, Google tokens, the Google client
  secret, the tracking secret. **It is read/written through `/usr/bin/security`** (write via `security -i` on stdin
  so secrets never appear in `ps`), NOT through this app's own SecItem calls. Reason: macOS pins app-owned
  items to a per-binary `cdhash:` *partition* that changes on every rebuild, so even with a stable signing identity
  the password prompt came back after each update; the Apple tool's items are trusted to `/usr/bin/security`
  (`anchor apple`, partition `apple-tool:`), which never changes. Older layouts (`vault-v1` direct item, one item per
  secret) migrate automatically on first launch (the only moment a prompt can occur). Never read the Keychain per
  render and never add items via SecItemAdd from the app (that reintroduces the cdhash pin).
- Polling (no IDLE): `Prefs.refreshMinutes`. New-mail and open notifications go through `Notifier`.
- **Conversations:** `MessageSummary.threadKey` groups list rows (Gmail threadId, otherwise
  References root / In-Reply-To / normalized "Re:" subject). Opening a message calls
  `provider.thread(for:)`: Gmail uses `threads.get`; IMAP searches Inbox + Sent by subject and keeps
  the matches linked by References (`IMAPProvider.assemble`, unit-tested). The reader (`ReaderView`)
  shows ordered `MessageCard`s, with the latest and unread messages expanded and attachments on each card.
- **Message bodies** render in `MessageBodyView` (`Views/HTMLView.swift`). Page JS is off and a strict CSP
  applies, but our script runs in the `.defaultClient` content world. It reports content height (so cards
  sit in one ScrollView; `PassthroughWebView` forwards scroll-wheel events) and hides quoted history
  (`QuoteStripper.htmlScript`: Gmail, Apple, Outlook web/desktop, Yahoo, Proton, our own `.ember_quote`).
  Plain text uses `QuoteStripper.plain`. Each card has a "Show quoted text" toggle. This was verified headless,
  using an NSHostingView in an off-screen window (see git history / ask for the harness).
- **Scheduled send** (`ScheduleStore`, `scheduled-sends.json`): the app sends due items every 20 s
  while running (window can be closed; terminate-on-last-window is off) and catches up on launch.
  Failures retry after 5 min. **Reply reminders** use `UNCalendarNotificationTrigger`, so macOS delivers
  them even when the app is closed. Notification actions (Reply / Snooze) come back through
  `AppDelegate` → `.emberNotificationResponse` → `AppState.handleNotification`. Replying to a thread
  clears its reminder.
- **Drafts:** Compose autosaves every 10 s when content changed (`ComposeDraft.contentFingerprint`), has a
  Save Draft button (⌘S) and Discard, and saves on window close. `AppState.saveDraft` → `provider.saveDraft`.
  IMAP appends a new copy (`\Draft \Seen`) to Drafts and then deletes the old one by Message-ID
  (`IMAPClient.deleteMessages`). Gmail uses `drafts.create/update/delete`. `ComposeDraft.draftRef` tracks
  the saved copy; sending or scheduling deletes it. Drafts carry an `X-Ember-Draft` header (base64 JSON
  `DraftMeta`), so "Edit Draft" (`AppState.resumeDraft`) restores the editable body separately from the
  signature and quote. Drafts made in other apps resume with their plain text as the body.
- **Calendar:** controls live in the window toolbar (no extra header row). `MonthGridView` must use
  `store.monthGridDays` (always 42 days), never `visibleDays`, which shrinks in Day mode. That caused a
  crash when switching Month → Day.
- **Sidebar All / Simple:** `Prefs.sidebarMode`. Simple shows `AppState.simpleMailboxes(for:)`: the chosen
  folders (`simpleFolders`, UserDefaults; default Inbox/Sent/Drafts), plus hidden folders where
  `canPopUp` holds and unread > 0, plus the current selection. Unread counts for hidden folders are fetched
  in Simple mode via `provider.unreadCounts` (IMAP: one `LIST … RETURN (STATUS (UNSEEN))` with LIST-STATUS,
  otherwise STATUS per folder inside one lock; Gmail: labels.get in parallel).
- **Shortcuts:** `MailAction` + `ShortcutStore` (UserDefaults `customShortcuts`, nil = cleared) +
  `MailActionPerformer` (App/Shortcuts.swift). Shortcuts with ⌘/⌥/⌃ go into the menus (`menuShortcut`).
  Plain keys (Gmail-style) are handled by a local key monitor in `RootView`, only when the main window is
  key and no `NSText` has focus, so typing never triggers them. Writing actions (send, save draft) must have
  a modifier. Compose buttons read their shortcuts from the store.
- **Filter & bulk select** (`MessageListView`, `MailFilter`): a Filter popover plus a one-click Unread pill sit
  above the list. `filter.unreadOnly` fetches ALL unread mail from the server (`provider.unreadMessages`:
  IMAP `UID SEARCH UNSEEN`, Gmail `is:unread`, up to 300/folder) because the normal list only holds the latest
  60; the result (`filterUnread`) is kept as loaded so opened messages don't vanish mid-read. Other criteria
  (flagged, attachments, reminder, date, read receipt, person) are applied locally in `matchesFilter`. The filter
  persists across folders.
- **Multi-select (Finder-style):** the list is `List(selection: $app.selectedGroupIDs)` (a Set). Click, ⌘-click
  and (via our overlay) shift-click ranges and **shift-drag marquee** work. `MarqueeSelection.swift` is an
  invisible overlay whose local `NSEvent` monitor finds the `NSTableView` under the mouse (SwiftUI's List is a
  `SwiftUIOutlineListView`), handles shift+mouse events itself (consuming them) and calls `table.rows(in:)`; plain and
  ⌘ clicks are left to the List (only recorded as the shift-click anchor). It was tested headless with synthetic
  events (`NSApp.sendEvent`). One selected row opens in the reader (`selectedMessageID` is kept in sync
  with `selectedGroupIDs` in both `didSet`s); several show `MultiSelectionView` and a bottom action bar, and the
  shortcuts (archive/trash/read/flag) and context menu act on the whole selection via `AppState.bulk`, which only
  touches messages whose state actually changes so unread counts stay correct.
- **Read receipts UI:** there is no Read Receipts page. Sent-folder rows show `ReceiptLabel` next to the
  subject (green Read / orange Maybe read / grey tick) and the reader shows `ReceiptBanner`. `AppState.checkOpens`
  polls the Worker every 60 s and notifies on EVERY new open (automatic ones are labelled "may have opened");
  clicking the notification opens the account's Sent folder.
- **Updates:** `UpdateStore` (App/) checks `UpdateConfig.repo`'s latest GitHub Release (public repo, unauthenticated API) on launch and every 6 h, plus
  App menu → Check for Updates… and Settings → General. `UpdateBar` (RootView) offers What's new / Update Now / Later / Skip This Version. Install = download the
  `.zip`, verify the `.sha256`, unzip with `ditto`, check bundle id + version + `codesign --verify`, then a detached script swaps the bundle after quit and relaunches.
  Pure logic (`AppVersion`, `UpdateLogic`) is unit-tested. Pushing to `main` does NOT update installs; only a Release does.
- **Signatures:** per account, either plain text or HTML (`signatureHTML`, `useHTMLSignature`) with
  inserted images stored in `signatureImages` and sent as `multipart/related` inline parts
  (`cid:`). Only referenced images are attached.
- The sidebar and the Today inspector are mutually exclusive (`RootView` watches both), because the
  window can't fit sidebar + list + reader + inspector.

## Read receipts
- With tracking on, outgoing HTML gets `<img src="https://<worker>/p/<22-char id>.gif">`.
  `TrackedMessage` maps the tracking id to the Message-ID header and Gmail id. The app polls
  `GET /api/opens?keys=…` (no shared secret: each message has a random `readKey` stored in `TrackedMessage`; the pixel id is
  the first 32 hex chars of SHA-256(readKey), so recipients can't derive the key). Worker response per key: `[{t, ua, city, country, org}]`.
- Opens within 15 s of sending are ignored. `TrackingStore.stripPixels` removes our own pixel before
  rendering, so the sender viewing Sent never counts as an open.
- Classification: GoogleImageProxy = Gmail (reliable). Apple ASN = Mail Privacy Protection prefetch,
  shown as "may be automatic" (orange). Keep UI copy honest about this.
- Optional MDN (`Disposition-Notification-To`) checkbox in Compose.

## Known limitations / next steps
- SMTP is implicit TLS (465) only; STARTTLS on 587 needs a Stream/CFStream-based connection.
- No IMAP IDLE, no offline body cache, no rich-text compose, no multi-select
  bulk actions yet. IMAP threads only search Inbox + Sent (+ the current folder), with up to 40 matches each.
- Scheduled sends need the app running (Mac awake) at send time; otherwise they go out on next launch.
- Without `setup-signing.sh` (ad-hoc signing), macOS asks for Keychain access once after each rebuild.
- **Local config (gitignored):** `Sources/EmberMail/Services/LocalConfig.swift` (Google Client ID, Worker URL) and `server/tracking-worker/wrangler.toml`
  (KV id, domain). Copy from the `.example` files on a fresh clone; builds fail without LocalConfig.swift.
- **Google sign-in:** the Client ID comes from `LocalConfig`; the secret is a Worker secret and the Worker's
  `/oauth/token` + `/oauth/refresh` do the exchange (app never sees the secret). There is no Google settings tab.
- **Settings:** nothing autosaves; each tab keeps draft @State and a `SaveBar` (Save/Revert, ⌘S). Shortcuts apply live while
  editing but are restored on Revert / closing without saving.
- Google OAuth app in "Testing" status: refresh tokens expire after 7 days (see docs/SETUP.md).

## Conventions
- SwiftUI first; AppKit only through small representables (WKWebView, NSWorkspace).
- Never use `Color.clear.frame(width:)` (or any Color/Shape with one dimension set) as a spacer inside
  stacks: it stretches along the other axis. Use `Spacer().frame(width:height:)`. This ballooned the
  calendar day header.
- Keep network/parsing code UI-free and covered by `Tests/main.swift`.
- User-facing strings: short, plain and friendly. Errors appear as a dismissible banner, never a crash.
- Don't log secrets or message bodies.
